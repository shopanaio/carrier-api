# @shopana/ukrposhta-api-client

Typed client for the [Ukrposhta](https://dev.ukrposhta.ua/documentation) API on `@shopana/carrier-core`. It is a thin wrapper: every method sends one documented request and returns the service's answer as typed data, without interpreting it.

Covered: the eCom API (addresses, clients, shipments, price calculation, shipment groups and form 103a, stickers and printed forms, courier collection, shipment management after dispatch, delivery notifications, documents back, domestic letters, international price and forms, countries, barcodes, banks, cash-on-delivery transfers), status tracking and the address classifier.

## Credentials

Each service takes its own bearer:

| Service            | Credential                       | Client                            |
| ------------------ | -------------------------------- | --------------------------------- |
| Status tracking    | tracking bearer                  | `createUkrposhtaTrackingClient`   |
| Address classifier | eCom bearer                      | `createUkrposhtaClassifierClient` |
| Tracking + classifier | tracking bearer and eCom bearer | `createUkrposhtaPublicClient`   |
| eCom and forms     | eCom bearer + counterparty token | `createUkrposhtaContractClient`   |

The environment defaults to `production`: pass `environment: 'sandbox'` (host `dev.ukrposhta.ua`, its own bearer and token) for tests. The documentation names no sandbox for tracking and the classifier; pass `baseUrl` if you have one. The eCom client adds the token (`?token=`) only to operations that take it. Secrets are strings or functions (`() => string | Promise<string>`) and are masked in logs. `transport` is optional and defaults to the fetch transport of carrier-core.

## eCom

```ts
import { createUkrposhtaContractClient } from '@shopana/ukrposhta-api-client';

const client = createUkrposhtaContractClient({
  environment: 'sandbox',
  bearer: process.env.UKRPOSHTA_BEARER!,
  counterpartyToken: process.env.UKRPOSHTA_TOKEN!,
});

const address = await client.addresses.create({ postcode: '04071', city: 'Kyiv' });
const shipment = await client.shipments.create({ sender: { uuid }, recipient: { uuid }, deliveryType: 'W2W', parcels });
const sticker = await client.labels.getSticker(shipment.uuid);
```

Every service is mounted on the client: `addresses`, `clients`, `shipments`, `pricing`, `shipmentGroups`, `labels`, `courier`, `management`, `transfers`, `barcodes`, `reference`, `deliveryNotifications`, `documentBack`, `letters`, `countries`, `payments`.

Methods the documentation describes differently from the Swagger, or that need care (batches, binary answers), are written by hand with the documented names. All other operations of the Swagger snapshot are generated by `yarn generate` from `contracts/ukrposhta-ecom.openapi.json` and take one argument with the path parameters, the query parameters and `body`:

```ts
await client.letters.getLetter({ uuidOrBarcode: '...' });
```

`GENERATED_OPERATIONS` lists them. Operations that only the current documentation lists (letter and international tariffs, forms 107, 119e and 20e, payments with an electronic stamp, signed notifications, country availability, bonus shipments) are written by hand too. The Swagger models are exported as `ApiTypes`. Files (stickers, forms) are returned as `{ contentType, data }`. Weights are in grams, sizes in centimeters (`length` is the longest side), prices in UAH.

Things the API enforces and the client does not check: a shipment is deleted only while it is `CREATED`; a group closes when its shipments are registered; cash on delivery of a sole proprietor or company goes to a bank account only; Express and Standard are priced by volume and need all three sizes. A shipment creation is never repeated automatically after a server error or a lost connection: the carrier may have created it.

## Public services

`createUkrposhtaPublicClient` mounts tracking and the address classifier on one client: `{ tracking, classifier }`. The two services take different bearers, so the config has `trackingBearer` and `classifierBearer` (optional; a service without one sends no `Authorization` header and Ukrposhta answers 401) and per-service `trackingBaseUrl` / `classifierBaseUrl`. `environment`, `transport`, `retry`, `timeoutMs` and `logger` are shared. The single-service factories below take one `bearer` and remain for callers that need only one service.

```ts
import { createUkrposhtaPublicClient } from '@shopana/ukrposhta-api-client/public';

const ukrposhta = createUkrposhtaPublicClient({
  trackingBearer: process.env.UKRPOSHTA_TRACKING_BEARER!,
  classifierBearer: process.env.UKRPOSHTA_ECOM_BEARER!,
});
const events = await ukrposhta.tracking.getStatuses('0500100031143');
const offices = await ukrposhta.classifier.getPostOffices({ postIndex: '01001' });
```

## Tracking

```ts
import { createUkrposhtaTrackingClient } from '@shopana/ukrposhta-api-client/public';

const tracking = createUkrposhtaTrackingClient({ bearer: process.env.UKRPOSHTA_TRACKING_BEARER! });
const events = await tracking.tracking.getStatuses('0500100031143', { lang: 'en' });
```

Batches take up to 50 barcodes for all statuses and 100 for last statuses (`TRACKING_MAX_BARCODES_*`); the service rejects more. A return to the sender arrives as event `41000` with `eventReason_id: 10`; `effectiveEventCode` turns it into `41010`, and `UKRPOSHTA_EVENT_LIFECYCLE` maps event codes to lifecycle statuses (Annex B).

## Address classifier

```ts
import { createUkrposhtaClassifierClient } from '@shopana/ukrposhta-api-client/public';

const classifier = createUkrposhtaClassifierClient({ bearer: process.env.UKRPOSHTA_ECOM_BEARER! });
const answer = await classifier.classifier.getPostOffices({ postIndex: '01001' });
```

Methods return the XML-derived JSON envelope as it is: `Entries.Entry` is one object for a single hit, an array for several, and the whole answer is empty for none. Each endpoint has its own record type with the fields of the documentation (values are strings or null). Search operations need at least one filter, otherwise the service answers an empty body; it also limits the request rate.

## Errors

Every failure is a `CarrierError`. `UPExxxxx` codes from Annex J map to categories by group (validation, not found, status, PDF, authentication, database, invalid operation, internal); only 5xx and 429 answers are retryable.

## Contracts

`contracts/ukrposhta-ecom.openapi.json` is the SwaggerHub snapshot of the eCom API; `contracts/README.md` lists where it disagrees with the documentation (the client follows the documentation).

## Tests

`yarn workspace @shopana/ukrposhta-api-client test` checks the requests (method, path, query, body, headers) and the raw answers against HTTP mocks (`__tests__/helpers`). `__tests__/documented.test.ts` calls every public method and compares the requests with the list of operations of the current documentation (`__tests__/fixtures/documented-operations.json`, from the eCom documentation of 02.09.2026, the letters documentation of 07.10.2026 and the international documentation of 16.10.2026). `yarn workspace @shopana/ukrposhta-api-client test:e2e` runs smoke tests against the real sandbox and is never part of the normal run: it skips every suite whose variables are not set (`UKRPOSHTA_SANDBOX_BEARER`, `UKRPOSHTA_SANDBOX_TOKEN`, `UKRPOSHTA_SANDBOX_TRACKING_BEARER`, `UKRPOSHTA_KNOWN_BARCODE`; see `e2e/env.ts`).
